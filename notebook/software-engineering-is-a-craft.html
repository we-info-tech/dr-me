Software Engineering
Is a Craft Skill

Anyone can learn the syntax of a programming language in a weekend. What takes years is developing the taste to know which correct solution is the right one — and the care to keep applying that taste when a deadline makes it tempting not to. That gap between "it works" and "it's well made" is the difference between a technical skill and a craft.

The central thesis

A skill produces code that works. A craft produces code that respects the people who will read it, run it, and inherit it.

Skill gets you to correct. Craft gets you to considered.

SkillCraft
Knows the syntaxKnows when not to use it
Makes it workMakes it work, read well, and last
Solves the immediate problemConsiders who inherits the solution
Applied consistently under pressureApplied especially under pressure
Measured by outputMeasured by what the output costs later

Skill is necessary but not sufficient. Plenty of technically skilled engineers ship code that is correct and still miserable to work with six months later — because correctness was the only bar they were clearing.

Craft is a practice, not a certificate

Trades — woodworking, cooking, tailoring — treat skill as a starting point and craft as something built through repetition, feedback, and correction. Software engineering works the same way, even though the industry rarely frames it that way:

  • Deliberate repetition: writing the same kind of function, module, or interface many times is how naming, structure, and error handling stop being decisions and start being instinct.
  • Feedback loops: code review, incidents, and being the one paged at 3 a.m. for your own code are the craft's version of a master looking over an apprentice's shoulder.
  • Correction, not just completion: a craftsperson revisits and improves past work; treating old code as "done and untouchable" is how craft atrophies into mere output.

Taste: the part that can't be checked by a linter

A linter can catch a missing null check. It cannot tell you that a function is doing three unrelated things, that a name is technically accurate but misleading, or that an abstraction is solving a problem nobody has yet. That judgment — knowing which correct code is still the wrong code — is taste, and it's earned by seeing enough bad decisions age badly.

  • Naming as a craft decision: a name is a promise to the reader about what a thing does. A vague name is a small, compounding tax on everyone who reads it after you.
  • Simplicity as restraint: the easy version of craft is adding more — more abstraction, more configuration, more flexibility. The harder, more valuable version is knowing what to leave out.
  • Consistency over cleverness: a clever one-liner that only the author can parse is a craft failure dressed up as a craft success.

Care under pressure is the real test

Anyone can write careful code when there's no deadline. Craft shows up in what an engineer keeps doing when they're tired, behind schedule, and nobody would notice if they cut a corner — still naming things clearly, still writing the test, still leaving the code slightly better than they found it. The moments craft is most tempting to abandon are exactly the moments it matters most, because that's when bad shortcuts get permanently baked into a system.

Deep core principles

  • Respect is the output: well-crafted code is a form of respect for whoever reads it next — including your own future self.
  • Craft compounds, sloppiness compounds faster: every shortcut becomes the baseline the next person builds on top of.
  • Taste is trained, not innate: it comes from seeing enough consequences of bad decisions to recognize them earlier next time.
  • The bar is invisible until it's crossed: nobody notices well-crafted code being easy to work with — they only notice when it isn't.

Final summary

Software engineering rewards technical skill quickly, but it rewards craft slowly and quietly — in the codebases that stay pleasant to work in years later, and the engineers whose work other people trust without checking twice. Skill gets the code to work. Craft is the discipline of still caring once it does.
