Coding Is Dead?
AI Missed the Funeral

Every few years, something announces the death of programming — 4GLs, visual programming, no-code, low-code, and now AI code generation. Each time, the obituary is written for "coding" in general, when what actually died was the cheapest, most mechanical part of it. AI hasn't ended software engineering. It has moved the job further from typing and closer to judgement.

The central thesis

AI didn't kill coding — it killed the version of coding that was already the least valuable part of the job.

An obituary that keeps getting rewritten

This isn't the first time the industry has declared programming over. Fourth-generation languages promised to let business analysts skip programmers. Visual programming promised drag-and-drop software with no code at all. No-code and low-code platforms promised the same, a decade later, with better marketing. Each raised the level of abstraction — and each time, the demand for people who deeply understand systems went up, not down, because someone still has to decide what to build, notice when the abstraction leaks, and fix it when it breaks in a way the tool never anticipated.

What AI actually replaces

AI code generation is genuinely good at the parts of coding that were always closer to typing than thinking:

  • Boilerplate and scaffolding: CRUD endpoints, config wiring, repetitive test setup — pattern-matched, low-judgement code.
  • Syntax and API recall: remembering the exact method signature or standard-library call, something search engines were already doing most of anyway.
  • First-draft translation: converting a clearly specified idea into a first pass of working code.

None of this was ever the hard part of the job for an experienced engineer. It was the part junior engineers spent the most time on — which is exactly why the disruption feels sharpest at the entry level.

What AI can't replace — and makes more valuable

  • Knowing what to build: AI answers the prompt it's given; it doesn't discover that the prompt was solving the wrong problem.
  • System understanding: generated code is locally plausible and often globally wrong — it doesn't know your system's history, constraints, or the incident that led to a defensive check three files away.
  • Verification: someone has to read the output and decide if it's actually correct, secure, and maintainable — a skill that requires being able to write the code yourself, not just accept what's generated.
  • Debugging root causes: AI is fluent at proposing plausible fixes; it's far weaker at the kind of causal reasoning that finds why a distributed system is intermittently failing.
  • Taste and trade-offs: deciding between two working solutions based on long-term cost, team skill, and operational reality is still a human judgement call.

The new bottleneck is verification, not generation

When code was expensive to write, writing it was the bottleneck. Now that a plausible first draft is nearly free, the bottleneck moves to whoever has to decide if that draft is trustworthy — and reading unfamiliar code carefully enough to trust it is often harder than writing it yourself. Teams that treat AI output as "done" instead of "a draft that needs review" are the ones who accumulate the most expensive kind of technical debt: code nobody fully understands, because nobody had to think hard enough to write it.

Why the entry-level anxiety is real but misplaced

The genuine disruption is that AI removes the easiest reps junior engineers used to learn on — writing boilerplate was tedious, but it was also how instincts about structure and naming got built. The fix isn't assuming coding is over; it's being deliberate about building judgement through code review, debugging real incidents, and reading other people's code, since the old path of "learn by typing a lot of simple code" is narrowing.

Deep core principles

  • Abstraction shifts don't remove engineers, they relocate the work: every previous "end of programming" made engineers more valuable at a higher level, not obsolete.
  • Cheap generation raises the price of verification: the skill that matters more every year is the ability to tell good code from plausible code.
  • Judgement was always the scarce resource: typing speed was never what separated senior engineers from junior ones.
  • Tools change the job before they change the title: "software engineer" will mean something different in practice long before the role disappears in name.

Final summary

Coding isn't dead — the part of it that was pure transcription is. What's left, and what's growing in importance, is exactly the part AI can't do on its own: knowing what to build, understanding the system it lives in, and being able to tell whether the output in front of you is actually right. AI didn't attend coding's funeral. It just took over writing the first drafts of the eulogy.
